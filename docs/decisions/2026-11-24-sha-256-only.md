# 2026-11-24: SHA-256 is the only key hash in 1.x

Team Leader bot, 2026-11-24, under Luca's rule "standard and safe". From the
multi-model package analysis of 2026-11-24 (issue #40).

| Item | Decision | Why |
| --- | --- | --- |
| Key hash algorithm | **SHA-256 of the whole presented token is the only algorithm in 1.x.** `hash_algorithm` stays `sha256` on every row, and `TokenCodec::match()` refuses any other value (fail closed, after a dummy compare). | API keys carry about 190 bits of CSPRNG entropy (32 base62 characters), so a fast unsalted hash is the standard choice (GitHub, Stripe): a slow password hash adds latency to every request without adding resistance to guessing. One algorithm keeps verification constant-time and the lookup by `key_hash` unique. |
| Changing the algorithm | **Only in a major release.** A new algorithm needs a new `hash_algorithm` value, dual verification during a migration window, and a rehash of every row on next use or at rotation. | `hash_algorithm` is a stored value (`docs/public-api.md`, storage formats); products persist it, so accepting a new value is a contract change, not an addition. The column exists from 1.0 so the move needs no migration. |
